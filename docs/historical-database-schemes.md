# 历史水文资料库与项目方案（2026-10-16）

## 日常使用

完整历史数据库 → 新建方案或打开同事优选方案 → 选择洪水与计算条件 → 保存版本 → 自动准备输入 → 计算并保存成果。

水文资料库的“实测资料、洪水目录、入库记录”统一查询工作区历史数据库。入库记录展示实际导入文件、站点和覆盖情况；不再把四份雨流加工结果当作四个日常资料来源。模型与资料中的“流域与站网”维护中文站名、出口水文站和新方案默认处理规则，站号与MDB别名留在详情。

同事测试MDB是原方案输入的交付载体。打开同事方案继续使用原冻结输入；新建方案使用完整历史库。输入快照与加工记录由系统管理，在方案中的“方案原始输入与处理记录”可追溯，无须另选资料包。

方案默认查看，浏览过程、筛选和翻页不修改条件。编辑后可以保存新版本、放弃修改或另存。改名仅修改名称；旧版本及关联成果保留。参数库和状态库继续保存成果中可以复用的参数、起算规则与完整末状态。

## 修改条件与复算

修改场次、用途、时段、站网或处理规则，保存前提示新版本将从历史库重新准备全部选用资料，不拼接旧MDB雨流和新库雨流。在率定设置的“起算条件与算法细项”中可明确选择“采用当前站网与处理规则”，先写入草稿，保存版本时确认重建。仅修改模型参数保留原输入；已准备过的历史库方案通过冻结绑定复用原输入，即使当前实测记录后来更新也不替换。

部分原交付联合率定使用专用初始种群，保存的河道参考配置仅适用于原搜索。改变输入后不继续声称是原方案搜索：弹窗说明转为当前初值，算法、预算、种子及范围保留。“率定设置”提供“采用原方案最佳参数作为初值”，由用户明确替换产流和汇流初值。无有效河道初值时仍阻止计算；不会偷偷替换成默认参数。新增早于连续起点的洪水时，还须主动调整“连续演算开始时间”，避免原2020年起点误用于2007年洪水。

“按原条件复算”读取成果的冻结请求、实际输入、随机种子、原程序及完整初态，不重新准备当前库。缺文件、程序或状态时明确拒绝复现，不能用最新资料或默认条件代替。

新输入的缓存摘要包括实际站点时段记录、站网、空间配置、处理规则、科学条件和准备程序。相同准备任务并发复用；参数变化不混用产流状态。空间配置与旧年度NC、旧流量表分离，历史库2007年不再受旧NC年份限制。

## 资料状态与2007年

历史库2007年含43,800条站点雨量、8,760条流量及8,760条水位记录，公共目录中有5场2007年洪水。

“原始记录缺测”“尚未生成网格”和“不满足率定质量要求”分别处理。过程接口先保留实测雨、流量、水位，网格生成失败也返回已读取实测；原始记录不自动标为QC通过。覆盖起止日期只表示边界，不承诺中间每小时完整。

2007年3月14日至25日场次已完成实测查询、网格生成、保存参数模拟与冻结复算。3月14日和4月22日场次的分场率定发现 `RUNOFF_PRECIPITATION_RATIO_EXCEEDS_MAXIMUM`，属于原水量平衡门槛，未降低阈值。可以查看原始过程；模拟与率定质量准入分开判断。

## 接口与验证

基础路径 `/api/model`：

- `GET database/catalog`：完整公共洪水目录、站点及覆盖；不依赖旧雨流包。
- `GET database/process?eventId=...`，或 `?start=...&end=...`：1至8784小时实测与派生网格，包含缺测、网格状态及摘要；场次与时段不能同时指定。
- `GET/POST database/network`：完整历史库站网及出口站；已有方案保留自己的冻结站网。
- `GET/POST database/preparation-defaults`：新方案默认插值幂次与最少有效站。
- `GET database/sources`：真实入库文件、数量与覆盖。
- `GET scheme-input-assets?schemeId=...`：方案交付与加工关联；不指定方案可核对待关联记录。
- 现有 `model-schemes` 保存完整版本和独立草稿，明确放弃和改名；`operations` 的 `rerun` 使用冻结成果。
