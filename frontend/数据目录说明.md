# 平台前端资源与运行资料边界

本文说明 `frontend/public/data` 中随源码管理的案例目录、轻量空间资料和展示 fixture。它不是运行数据库或模型输入库；正式查询、率定、模拟、状态续算和预报由 Python 后端从所选工作区读取资料并执行。

主要静态资源如下：

- `public/data/projects/catalog.json`：并行案例的总目录，目前登记三个案例，新增案例由此扩展；
- `public/data/projects/<project>/manifest.json`：能力、资料状态、分辨率和资源引用；
- `public/data/projects/<project>/<resolution>/spatial.json`：浏览器可读取的轻量空间文件引用；
- `datasets.json`：数据包、版本、时间范围和资料状态；
- `fixtures.json`：前端样例任务结果的目录，只保存引用和来源标记；
- `nananxi-xufan/input-preparation.json`：南安溪空间资料、实测观测、降雨空间化条件及后端缺口的统一输入准备目录；
- `nananxi-xufan/observations/event-data-packages.json`：已登记洪水场次的数据完整率、实测特征和年度文件引用；
- `src/services/projectCatalogService.js`：从 catalog 与 manifest 动态登记流域及模型尺度；
- `src/services/projectDataService.js`：统一加载与缓存；
- `src/services/resourceUrl.js`、`projectResourceService.js`：按清单来源解析相对资源路径；
- `src/services/caseAvailabilityService.js`：区分案例目录元数据、资料就绪状态和可用能力，不让缺资料的新案例复用其他案例；
- `src/services/forecastSubmissionService.js`、`calibrationSubmissionService.js`：组装并提交统一后端任务请求；Vite 开发模式将 `/api/model` 代理到本机服务；
- Vue 页面、Pinia Store：管理交互选择和页面状态；业务记录、任务队列和计算成果由后端及工作区保存。

原始 MDB、Excel、Shapefile、Arc/Info Grid、NetCDF 和旧程序不得直接复制到浏览器目录。空间浏览需要的边界、河网或预览应转换为适合浏览器读取的格式并保留来源说明；模型所需原始资料和计算输入按后端输入契约登记在工作区，不随静态前端资源读取。

南安溪实测资料目录可用以下脚本重新生成：

```bash
powershell -ExecutionPolicy Bypass -File scripts/build_nananxi_historical_data.ps1
node scripts/build_nananxi_event_packages.mjs
```

南安溪模型端标准输入由以下脚本生成，输出位于前端目录之外，不随浏览器静态资源发布：

```bash
python scripts/build_nananxi_delivery_package.py --help
```

该资料工具已按观察目录清单的位置解析年度文件，并兼容历史 `/data/...` 引用；临时工作目录使用系统临时目录，不在盘根创建。它默认不生成 ZIP，仅显式 `--create-zip` 才启用可选资料压缩，`--skip-zip` 保留兼容。它不是应用外发或安装工具，本轮没有运行全量转换或压缩。

本机 `交付包/南安溪-徐畈数据资料整合` 是未纳入 Git 的本地资料交付目录，不等同于前端运行目录，也不应被浏览器直接扫描。其来源内容包括站点、1 公里和0.1度实测降雨 NC，以及徐畈出口水位和流量 Excel。迁移或清理该本地目录前，应确认后端工作区或其他指定来源已有所需数据；源码克隆不会恢复这些文件。

前端提交资料引用、计算时段、断面、状态、参数版本和降雨空间化条件；实际输入核验、NC 读取及模型计算由后端执行。新增或更新浏览器可见的案例空间资料时，才需要同步维护本目录的清单与资源。

当前 `src/data/basin.js`、`src/data/selinco.js` 等模块属于兼容层。后续按页面逐步改用项目数据服务，在完成全部调用迁移和回归验证前不直接删除或移动。

## 可移植资料构建工具

这些工具不属于浏览器运行时。日常前端开发不要求安装 GIS/Python 依赖，也不应为了运行前端而重新生成全部原始资料。

- `build_project_assets.py`：通过 `--cases-root`、`--china-dem-1km` 指定案例资料和 DEM；环境变量为 `XAJ_CASES_ROOT`、`XAJ_CHINA_DEM_1KM`。输出仍在当前前端的 `public/data/projects` 内。
- `build_selinco_assets.py`：显式指定 `--package-root`、`--dem-root`、`--stream-root`；也可使用 `SELINCO_PACKAGE_ROOT`、`TIBET_DEM_ROOT`、`SELINCO_STREAM_ROOT`。不依赖固定日期目录或其他盘符的 DEM。
- `build_nananxi_historical_data.ps1`：默认相对于脚本查找资料；可通过 `-DatabasePath`、`-FloodWorkbookPath`、`-OutputRoot` 指定源和输出。
- `build_nananxi_event_packages.mjs`：默认处理南安溪资料包，工作目录由脚本位置确定，不依赖命令启动时的当前目录。

构建工具可能重写生成资料。本轮只进行代码与路径整理，没有重跑 MDB、GIS 或 NetCDF 全量转换。

色林错的原始来源包位于工作区 `实际案例/色林错案例/` 下的原始资料与河网资料目录。两包内部各有一层来源自带同名目录，构建参数须指向内层数据根目录；完整相对路径见该案例的 `资料来源说明.md`。脚本使用显式参数，不把这些目录写死为全局默认。

## 路径要求

- 清单中的静态资源优先使用相对于案例目录或清单文件的路径。
- 不写入 `F:\...`、`C:\...`、用户目录等机器专属路径。
- `public/data` 中已有的 `/data/...` JSON 引用已改为相对引用；源码内少量历史入口仍由统一 URL 解析层适配 `import.meta.env.BASE_URL`，不作为网站根路径直接请求。
- `filePattern`、`source`、`catalog` 等字段只记录资料血缘或外部输入位置，不等于浏览器可以访问本机文件。

维护检查：在 `frontend` 目录执行 `node scripts/normalize_json_resource_paths.mjs`，默认只检查；仅在明确需要重写旧路径时才加 `--write`。
