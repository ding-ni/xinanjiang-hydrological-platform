# 分布式新安江水文模型业务化预报平台前端施工图

> 文档状态：前端实施待确认版  
> 更新日期：2026-07-31  
> 实施原则：先把前端页面、交互、数据状态和完整作业流程做实，再接后端计算服务。  
> 本文范围：前端信息架构、页面规格、前端样例数据、任务模拟、实施顺序和验收标准。

## 1. 建设目标

系统定位为：

**面向多流域应用的分布式新安江水文模型业务化预报与可视化前端系统。**

系统只采用一个核心模型框架，即分布式新安江水文模型。南安溪-徐畈、里龙普曲和色林错是三个独立流域实例，共用相同操作流程，分别拥有自己的空间配置、数据、参数、状态和运行档案。

前端是可以直接操作的模型业务工作台，不是只读看板。完整操作主线为：

    选择流域和空间分辨率
      -> 选择数据、参数、状态和计算条件
      -> 提交模型作业
      -> 查看运行状态
      -> 分析结果
      -> 保存、归档或按原条件重算

当前阶段即使没有后端，也必须通过明确标注的前端样例任务走通上述流程。后端接入后只替换任务执行和结果来源，不重新设计页面。

## 3. 全局页面框架

### 3.1 顶部栏

顶部栏从左到右固定为：

1. 系统名称；
2. 当前页面名称；
3. 流域选择器；
4. 空间分辨率选择器；
5. 当前项目名称；
6. 数据时刻；
7. 数据状态。

流域选项：

- 南安溪-徐畈；
- 里龙普曲；
- 色林错。

空间分辨率选项：

- 1 km；
- 0.1°。

项目名称只显示，不再作为模型选择器。三个项目均属于分布式新安江模型。

### 3.2 全局工作上下文

Pinia 中统一保存 `workContext`：

```js
{
  basinProjectId,
  spatialResolutionId,
  basinConfigVersionId,
  dataSourceId,
  inputBundleVersionId,
  parameterVersionId,
  stateVersionId,
  sectionId,
  issueTime,
  sourceTaskId
}
```

切换流域或分辨率时执行以下动作：

1. 更新地图范围和空间图层；
2. 清除不兼容的数据、参数、状态、断面和结果选择；
3. 加载新上下文的可选项；
4. 保留该流域与分辨率上一次有效选择；
5. 如果资料不足，显示缺项并禁用相关执行按钮；
6. 不把旧流域的图表或任务结果留在页面上。

上下文唯一键：

    contextKey = basinProjectId + ':' + spatialResolutionId

所有参数、状态、任务和结果必须带有 `contextKey`。

### 3.3 跨页面传递

页面跳转统一传递 `workContext`，不在各页面重新拼装业务条件。

| 来源 | 目标 | 自动带入内容 |
| --- | --- | --- |
| 雨水情监视 | 状态续算 | 流域、分辨率、观测数据版本、当前数据时刻 |
| 雨水情监视 | 洪水预报 | 流域、分辨率、观测数据版本、起报时刻 |
| 模型计算 | 状态续算 | 连续模拟任务、末时刻、参数版本、结果状态引用 |
| 状态续算 | 洪水预报 | 状态版本、参数版本、目标时刻 |
| 洪水预报 | 运行档案 | 预报任务编号和结果版本 |
| 运行档案 | 原作业页面 | 原任务全部条件和 `sourceTaskId` |

进入目标页面后自动填充字段，并显示“条件来自哪个页面或任务”。用户仍可修改，修改后必须重新执行任务。

## 4. 多流域与分辨率配置

### 4.1 状态定义

前端统一使用以下资料状态：

| 状态 | 页面含义 | 执行按钮 |
| --- | --- | --- |
| 真实资料 | 已接入真实或可追溯派生资料 | 按任务能力启用 |
| 前端样例 | 用于完整演示，明确不代表正式计算 | 启用并标注“样例运行” |
| 仅空间资料 | 只能展示地图和空间对象 | 需要时禁用 |
| 资料缺失 | 缺少任务必需输入 | 禁用并显示缺项 |
| 后端待接 | 前端条件与样例结果完整，正式服务未接入 | 使用前端样例执行 |

页面不得用虚构结果冒充真实结果，但允许使用清楚标注的前端样例完成交互验收。

### 4.2 流域能力矩阵

| 流域 | 分辨率 | 空间资料现状 | 小时输入现状 | 当前前端运行方式 |
| --- | --- | --- | --- | --- |
| 南安溪-徐畈 | 1 km | 源 DEM/SHP/河网/站点已核实，轻量前端文件待生成 | 真实小时雨量、水位和流量源资料已核实 | 接入预览后使用标注样例任务走完整流程 |
| 南安溪-徐畈 | 0.1° | 由现有 DEM/SHP 建立对应显示和配置，不重新划分流域 | 与项目真实小时资料关联 | 使用独立 0.1° 参数、状态和样例结果 |
| 里龙普曲 | 1 km | DEM、边界、河流和出口已核实 | 小时驱动与出口流量待确认接入 | 地图可用；缺少输入时任务禁用 |
| 里龙普曲 | 0.1° | 由现有空间资料建立对应配置 | 小时驱动与出口流量待确认接入 | 地图可用；缺少输入时任务禁用 |
| 色林错 | 1 km | 已有空间和降水前端资源 | 已有部分逐小时降水资料 | 保留现有样例流程并明确来源 |
| 色林错 | 0.1° | 已有对应空间配置 | 已有部分逐小时降水资料 | 保留现有样例流程并明确来源 |

所有流域在注册表中都显示 1 km 和 0.1°。是否可执行由 `capabilities` 和资料状态判断，不通过隐藏选项回避缺项。

## 5. 前端 Mock 任务系统

### 5.1 建设目的

在后端未接入时，率定、连续模拟、状态续算和洪水预报不能只是弹出“成功”提示。前端必须生成真实的任务对象，经历完整状态变化，返回对应样例结果，并进入运行档案。

### 5.2 前端目录

新增：

```text
app/src/services/
  taskService.js
  projectDataService.js
  adapters/
    fixtureAdapter.js
    httpAdapter.js

app/src/stores/
  tasks.js

app/src/fixtures/
  catalogs/
  runs/
    continuous/
    calibration/
    state/
    forecast/
```

页面和业务 Store 只调用 `taskService`，不得直接调用本地模型演示函数。现有 `xajParamEngine` 如需暂时保留，只能由 `fixtureAdapter` 包装为前端样例生成器，并在结果中标记 `resultSource: 'frontend-fixture'`。

### 5.3 统一任务类型

| `runType` | 中文名称 | 发起页面 | 主要结果 |
| --- | --- | --- | --- |
| `continuousSimulation` | 连续模拟 | 模型计算 | 连续过程、指标、末时刻状态 |
| `continuousCalibration` | 连续时段率定 | 模型计算 | 候选参数、连续评价、参数版本草稿 |
| `eventCalibration` | 洪水事件率定 | 模型计算 | 逐场过程、综合评价、参数版本草稿 |
| `stateInitialization` | 状态初始化 | 状态续算 | 初始状态空间场和状态版本 |
| `stateContinuation` | 状态续算 | 状态续算 | 目标时刻状态和状态版本 |
| `forecast` | 洪水预报 | 洪水预报 | 预报过程、空间结果和预报摘要 |

### 5.4 状态机

```text
draft
  -> queued
  -> running
  -> completed
  -> archived

queued/running -> cancelled
queued/running -> failed
completed --复制条件--> 新 draft
```

任务对象至少包含：

```js
{
  taskId,
  runType,
  contextKey,
  runConfig,
  status,
  progress,
  stageLabel,
  resultSource,
  resultVersionId,
  errorMessage,
  createdAt,
  startedAt,
  completedAt
}
```

### 5.5 Mock 行为

`fixtureAdapter` 固定执行规则：

1. 提交后立即生成任务编号；
2. 进入 `queued`；
3. 进入 `running` 并更新进度与阶段文字；
4. 根据 `contextKey + runType + fixtureScenarioId` 获取确定性样例结果；
5. 成功后进入 `completed`；
6. 点击停止后进入 `cancelled`；
7. 测试场景可以返回 `failed` 和明确错误；
8. 任务元数据和运行档案保存到 `localStorage`；
9. 大型图表和空间结果保存在静态 fixture 文件中，档案只保存引用；
10. 页面刷新后恢复任务、条件、结果引用和当前进度终态。

Mock 状态文字必须使用“前端样例运行”，不能显示“后端已计算”。

### 5.6 未来替换边界

正式后端接入时，`taskService` 方法保持不变，只将 Adapter 从 `fixtureAdapter` 切换为 `httpAdapter`：

```js
listOptions(context)
submitTask(runType, runConfig)
getTask(taskId)
cancelTask(taskId)
getResult(taskId)
archiveTask(taskId)
cloneTask(taskId)
```

当前前端阶段只实现上述方法的 fixture 版本，不开展后端开发。

## 6. 六个页面施工规格

### 6.1 雨水情监视

**路由与定位**

- 路由：`/realtime`；
- 名称：雨水情监视；
- 目标：确认当前流域空间、实时雨水情和资料完整性，并把当前条件带入后续作业。

**桌面布局**

```text
指标条：数据时刻 | 站点到报 | 1/3/6/24 h 面雨量 | 当前流量 | 预警

地图与图层（主区域）            站点状态/异常列表（右侧）

选中站点或断面的雨量—水位—流量过程（底部）
```

**保留**

- 现有 MapLibre 地图；
- 流域边界、DEM、河网、站点和网格图层；
- 雨量、水位、流量和异常状态；
- 进入洪水预报的快捷按钮。

**增加或调整**

- 顶部统一流域与分辨率选择；
- 数据源和数据版本只读摘要；
- 图层开关、时间步选择和站点类型筛选；
- “带入状态续算”和“带入洪水预报”两个明确操作；
- 真实资料、前端样例、资料缺失状态标签；
- 切换流域后自动定位到该流域范围。

**状态规则**

| 状态 | 页面表现 |
| --- | --- |
| loading | 地图骨架、指标占位、禁用跳转按钮 |
| success | 显示地图、指标、站点和更新时间 |
| partial | 可展示已有资料，缺项单独标识 |
| empty | 地图保留空间对象，时间序列区显示无资料 |
| error | 显示失败来源和重新加载按钮 |

**验收**

- 三个流域、两种分辨率均可切换；
- 切换后地图、站点、指标和数据说明同步更新；
- 缺少小时资料的里龙普曲不显示虚构过程；
- 跳转状态续算或洪水预报后，目标页自动带入当前上下文。

### 6.2 模型计算

**路由与定位**

- 路由：`/calibration`；
- 导航名称：模型计算；
- 一级页内 Tab：连续模拟、参数率定；
- 参数率定二级模式：连续时段、洪水事件。

**桌面布局**

```text
作业类型 Tab + 当前任务状态条

条件设置（左 360 px） | 过程图/空间结果（中） | 参数与范围（右 320 px）

事件/时段明细 + 评价指标 + 候选结果（底部）
```

**共同选择项**

- 流域和分辨率：继承全局上下文；
- 数据源/数据库逻辑名称；
- 输入数据包版本；
- 计算断面或入湖口；
- 基础参数版本；
- 模拟时段或洪水事件集。

**连续模拟**

选择项：

- 开始和结束时间；
- 预热期；
- 初始状态版本；
- 输出时间步长；
- 结果项目。

操作：

- 开始连续模拟；
- 停止；
- 按当前条件重算；
- 保存末时刻状态；
- 归档运行。

连续模拟不显示优化算法、目标函数、参数上下限和迭代次数。

**连续时段率定**

选择项：

- 率定期和验证期；
- 预热期；
- 优化算法；
- 目标函数与权重；
- 参与率定的参数及上下限；
- 算法必要控制项。

**洪水事件率定**

选择项：

- 已登记洪水事件；
- 每场事件用途：率定、验证、独立检验；
- 率定断面；
- 优化算法；
- 洪峰、峰现时间、洪量和过程拟合指标；
- 参数范围和算法控制项。

洪水场次页只选择已登记场次，不提供“新增并切割洪水”的自动处理。场次登记入口放在“模型与资料 -> 洪水场次”。

**算法目录**

前端样例阶段提供：

- SCE-UA；
- DDS；
- DE；
- PSO。

每个算法由目录数据定义名称、说明、兼容模式和需要显示的控制项。页面不得用四套独立表单硬编码。

**结果区域**

- 降雨—实测—模拟过程；
- 连续评价或逐场洪水评价；
- NSE、KGE、RMSE、PBIAS；
- 洪峰误差、峰现时间误差和洪量误差；
- 当前参数与候选参数对比；
- 任务来源、分辨率、数据版本和结果来源；
- 保存参数版本或放弃候选结果。

**按钮规则**

- 必填条件不完整：执行按钮禁用并列出缺项；
- 权重合计不为 1：率定按钮禁用；
- 参数下限大于上限：率定按钮禁用；
- 任务运行中：设置区锁定，停止按钮启用；
- 修改已完成任务的任一条件：结果标记为“旧条件结果”，必须重算；
- 只有率定任务可以保存参数版本；
- 只有连续模拟可以保存末时刻状态。

**验收**

- 三种作业均有独立入口和正确按钮文字；
- 连续模拟不出现率定控件；
- 洪水事件只能从事件目录选择；
- Mock 任务可以完成、停止和失败；
- 完成结果可以进入运行档案；
- 1 km 和 0.1° 的参数与结果不能串用。

### 6.3 状态续算

**路由与定位**

- 路由：`/state`；
- 名称：状态续算；
- 页内模式：状态初始化、状态续算、状态诊断。

**桌面布局**

```text
可用状态版本带（顶部）

初始化/续算条件（左） | 状态空间分布（中） | 状态来源与完整性（右）

状态变量时间变化（底部）
```

**状态初始化**

选择项：

- 初始化方式；
- 参数版本；
- 初始化时刻；
- 默认状态方案或历史参考状态；
- 适用空间范围。

**状态续算**

选择项：

- 来源状态版本；
- 起始时刻；
- 目标时刻；
- 观测输入数据版本；
- 参数版本。

操作：

- 执行初始化；
- 执行状态续算；
- 停止；
- 保存状态版本；
- 采用为洪水预报起算状态。

**状态诊断**

通用状态变量：

- WU；
- WL；
- WD；
- S；
- 张力水相对蓄量；
- 自由水蓄量。

高寒能力启用时增加：

- SWE；
- 积雪深度；
- 雪层液态水；
- 冻土状态；
- 冰川消融结果。

高寒变量由项目 `capabilities.coldRegion` 控制，不使用 `isSelinco` 作为判断条件。

**按钮规则**

- 目标时刻不得早于来源状态时刻；
- 来源状态、参数和输入数据必须属于同一 `contextKey`；
- 状态任务完成前不能保存状态版本；
- 保存后生成新 `stateVersionId`；
- 点击“用于洪水预报”后跳转并锁定对应状态版本；
- 里龙普曲缺少输入时，地图仍可查看，续算按钮显示缺项并禁用。

**验收**

- 页面不再只有“选择已有状态”；
- 初始化和续算都能走完 Mock 任务；
- 保存后的状态出现在版本带和运行档案；
- 状态来源、参数、输入和父状态可以追踪；
- 高寒变量只在能力启用时出现。

### 6.4 洪水预报

**路由与定位**

- 路由：`/forecast`；
- 名称：洪水预报；

**桌面布局**

```text

洪峰、峰现、洪量、分区贡献和历史对比（底部）
```

**预报条件**

- 预报断面或入湖口；
- 起报时刻；
- 预见期；

- 实测资料是否到达起报时刻；
- 降雨预报时次是否覆盖预见期；

- 停止；
- 条件调整后重新预报；
- 归档本次预报；
- 查看预报单；
- 复制为下一次作业。

**结果研判**

- 实测与预报过程连续展示；
- 雨量—流量组合图；
- 洪峰流量、峰现时间、洪量和预警等级；
- 子流域或计算单元空间结果；
- 当前预报与历史运行对比；
- 色林错各入湖口过程和全湖水量平衡摘要。

**验收**

- 从雨水情监视和状态续算进入时条件自动带入；
- 起报检查可以明确阻断或放行；
- Mock 预报显示完整任务进度和结果；
- 修改条件后旧结果明确失效；
- 归档后可以在运行档案中打开和复制。

## 14. 当前已知缺项

前端施工已完成，以下内容属于真实业务资料或后端联调缺口，不以虚构数据补齐：

1. 南安溪-徐畈正式参数版本和起算状态版本；
2. 南安溪-徐畈起报时刻之后的逐小时预报降雨；
3. 南安溪-徐畈连续时段模拟所需的蒸散发资料；小时尺度场次洪水率定、模拟和预报按 `0 mm/h` 处理；
4. 分布式新安江产流、坡面汇流、河道汇流和参数优化服务，以及请求字段的最终映射；
5. 里龙普曲小时降水、流量、气温、蒸发、冰雪冻土驱动资料和正式参数、状态版本。

这些缺项已在页面中以 `partial`、`empty` 或禁用原因如实显示。资料不完整的流域不能执行对应任务，也不会回退读取旧新安江或其他流域的数据。

## 15. 最终施工结论

本轮前端按照以下固定图纸实施：

    六个主页面
      + 三个真实流域实例
      + 每个流域两种空间分辨率
      + 统一工作上下文
      + 统一 Mock 任务系统
      + 可追踪运行档案
      + 未来可替换的后端 Adapter

前端完成的标准不是“页面已经画出来”，而是能够查看真实雨水情和降雨栅格，选择洪水场次，组织率定、状态预热和预报条件，并把完整请求交给模型服务。没有后端时不生成虚拟的南安溪参数、状态和模拟成果；后端接入后不改变现有操作流程。

## 2026-08-05：资料语义、回放与设置入口统一

- 页面统一使用“资料”“实测资料”“预报资料”表达数据用途，不把资料是否发生在过去作为业务分类；回放页改称“实测雨水情回放”，场次目录中的操作按钮改为“变更记录”，明确它只记录场次定义和状态的修改，不代表资料类别。
- 新增“资料与对象”设置页，统一显示出口水文资料、降雨资料、控制断面、资料共同覆盖范围和场次蒸散发，并允许修改预热期。率定页和连续模拟页继续沿用同一份设置，避免出现多个互不相同的预热期入口。
- 回放窗口按雨量与出口水文资料的共同覆盖范围限制日期输入；支持最新共同覆盖时段、指定时段和指定洪水场次三种选择。点击“刷新并载入最新资料”或资料页“更新资料目录”时，重新读取目录和年度资料，适配后续追加的新资料，不覆盖既有场次定义。
- 回放栅格随资料窗口按需生成，平滑雨量场只在图层打开时计算，并使用帧合并和缓存降低播放过程中的重复渲染；模型使用的 1 km/0.1° NC 数值不因展示平滑而改变。
- 洪水场次超出当前出口资料覆盖范围时保存为待核查并给出提示，不再阻止用户登记未来新增资料对应的场次；已有原始洪号、事件 ID 和变更记录保持不变。

## 2026-08-05：资料更新语义与回放交互收口

- 资料不再按“历史/实时”区分业务类型。页面和交付说明统一使用“实测资料”“资料覆盖范围”“最新共同覆盖时段”“已有运行记录”；“历史”只保留在确实描述过去洪水事件或修改记录的语境中。新增资料仍写入同一标准目录，目录更新后共同覆盖范围自动变化。
- 洪水场次台账和率定台账的洪峰表头支持点击排序：首次按 Qmax 从大到小，继续点击反向；缺失 Qmax 始终排在末尾。原始洪号、系统事件 ID、场次版本和变更记录不因排序或资料追加改变。
- 共同覆盖范围由统一服务计算，回放控件、资料设置页和最新资料加载共用同一结果。窗口支持最新共同覆盖时段、指定时段和指定洪水场次，不能载入雨量或出口水文资料不完整的时段。
- 资料与对象中的预热期和控制断面属于当前模型工作区设置，修改后写入浏览器本地工作区；刷新页面或切换到率定、连续模拟时继续使用同一设置。模型实际计算仍由后端读取该设置。
- 过程播放采用逐帧调度、窗口按需读取、降雨格点缓存和平滑雨量场的帧合并。平滑雨量场只改变地图显示，正式 1 km/0.1° NC 数值和模型输入不变。
- 年度资料和回放窗口采用有上限的浏览器缓存，监视页与降雨栅格共用已读取窗口；刷新资料目录时清空缓存并重新读取，避免新增资料被旧窗口遮住，也避免切换场次重复解析同一年度文件。
