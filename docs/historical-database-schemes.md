# 历史资料与方案边界

## 资料库

水文资料库统一提供实测记录、公共洪水目录、站网和入库来源。入库记录应能追溯实际文件、站点、时段和覆盖；覆盖边界不代表中间每小时完整，也不自动表示观测通过质量检查。

“原始记录缺测”“网格尚未生成”和“资料不满足率定质量要求”分别表示不同问题。网格生成失败时仍可查看已读取的实测过程；质量诊断不能改写原始观测。当前公共目录含226场，历史资料的实际覆盖以工作区数据库及查询结果为准。

## 方案输入与复算

新方案从当前登记的历史资料和站网准备输入。已保存方案绑定其实际输入、站网、处理规则、蒸散发与初态条件；之后数据库更新不会静默替换这些输入。改洪水时段、用途、站网或处理规则后，应保存新方案版本并重新准备所选资料。

同事交付的历史方案按原输入版本重放，不与当前历史库雨流混用。原始输入和处理记录应通过方案关联查看；名称、洪水编号或相近时间范围本身不是输入血缘证据。来源资料版本、空间定义或质控规则不同的结果不得合并比较为同一条件。

来源方案的复现边界为原接受的16个窗口：11场率定、3场验证、2场独立检验。原列表中一个721小时窗口超过原720小时门槛，未参与原率定；它只可在已核实来源条件的重放中用同一冻结参数补算。窗口重叠形成的物理洪水组不等于独立样本。原QC、float64驱动、空间目标和连续状态策略均属于来源条件，不能因当前质量诊断增加门槛而静默重写原接受名单。

“按原条件复算”使用成果冻结的请求、输入、随机种子、模型实现和完整初态。缺少其中任一必要来源时应明确拒绝复现；不能用当前默认资料、参数或实现冒充原结果。原始数据库和计算成果属于运行工作区，不包含在源码 Git 克隆中，迁移时通过工作区备份/恢复流程处理。

## 历史业务约束

- 同事原始窗口、原排除窗口和公共洪水目录是不同集合；重叠或同号窗口不可按洪号自动合并。
- 新增早于连续演算起点的场次时，必须明确调整连续起点，不能沿用不覆盖该时段的旧状态轨迹。
- 实测缺测不补零；配对水量只使用共同有效小时，不得表述为完整洪水总量。
- 旧状态可以查看和导出；缺少当前程序、输入或科学身份时不得直接续算或用于预报。
- 资料和参数变更创建新版本；既有方案、输入快照和成果记录保持原条件。

## 接口入口

主要接口位于 `/api/model`：`database/catalog` 查询洪水、站点和覆盖；`database/process` 查询实测与派生网格；`database/network` 管理站网；`database/sources` 查看入库来源；方案输入关联接口查看具体输入版本。完整请求和响应结构见[后端 API](../backend/API.md)。
