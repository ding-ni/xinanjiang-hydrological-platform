# 新安江水文计算平台

当前版本：1.12.0（2026-10-16）。仓库维护账号：`ding-ni`。

面向南安溪—徐畈 1 km 的单机水文计算平台，采用 Vue 前端、Python 计算服务和 SQLite 资料库，沿用原新安江产汇流数值内核。

日常启动在服务就绪后自动打开浏览器，成功的页面查询不滚动输出日志；启动窗口保留工作区、地址及异常提示。1.11.1的中文目录启动编码修复继续保留。1.11.2澄清产流网格、河网地形依据和同事参数方案的显示，水文计算条件沿用原方案。

雨水情主页可在“降雨显示”切换网格或平滑；两者显示同一资料版本、同一时次的网格雨量，面雨量统计和模型计算继续采用原网格。

水文资料库用于实测查询、洪水目录和覆盖缺测核对。参数率定先命名方案，再从完整洪水目录选择场次、划分用途并计算；满意后命名保存参数。日常“洪水模拟”只选择已保存参数与洪水或连续时段，后台自动准备雨流资料和起算状态。

2026-10-16：日常查询与新计算统一使用完整历史数据库，同事优选洪水纳入普通项目方案管理；旧交付输入保留用于原条件计算与复算。公共目录保持226场，2007年过程不再受旧NC年份限制，实测缺测、网格生成与率定质量检查分别显示。详见[历史库与方案更新说明](docs/historical-database-schemes.md)。

本轮水文任务工作台已把“方案 → 洪水过程 → 参数与起算条件 → 计算 → 命名成果 → 状态/断面查询”连成一条流程。1988-08-08 徐畈（二）过程已用历史库核查：站点累计39.3 mm、最大时雨量20.3 mm，面雨量首小时约3.5 mm；地图、过程图和时间轴使用同一份后台网格结果。成果按整次作业命名并冻结原条件，断面查询必须选择成果、洪水过程和断面。性能对照同时记录资料准备、数值预热、产流、汇流、状态保存等阶段；对照脚本注明编译缓存口径，不把缩短预热或评价期当作程序提速。源码提交不包含本机运行工作区、MDB副本或计算结果，业务数据仍由本机工作区管理。

明确支持场次自动率定、连续自动率定、场次模拟和连续模拟。连续率定默认从统一起点连续演算，每组候选重新形成自身状态轨迹，只有率定期参与搜索。验证与独立检验使用冻结参数评价，最终参数对应的场次或连续计算保存逐时状态及末状态。预算用完不标作收敛。当前使用现有蒸散发配置，多年资料按实际覆盖检查。当前操作见[方案与自动率定操作说明](方案与自动率定操作说明.md)。

历次作业在“计算成果”查看、比较、恢复条件和导出。模拟状态与河道流量从对应成果进入；继续模拟只填写结束时间。人工试调主图保持实测、本次模拟、上次模拟三条过程线。

“洪水预报”当前提供单次和逐小时滚动历史回算，使用实际逐格降雨，自动形成起报状态，固定参数并保存每次起报成果。实时资料接入、预报降雨和定时起报在布设时配置。专业设置集中在“模型整定”，同事17场资料与旧成果作为工作区记录保留。此前数值升级见[后端升级说明](20261012后端升级说明.md)。

## 从源码运行

在 Windows 上准备 64 位 Python 3.9、Node.js 和 npm，克隆仓库后，在项目根目录依次执行：

```powershell
cd frontend-demo/app
npm ci
npm run build:unified
cd ../..
.\安装平台.cmd
.\启动统一平台.cmd
```

服务默认地址为 `http://127.0.0.1:8878/`。源码仓库不包含已构建网页和本机 Python 环境，首次运行需要构建、安装。安装目录、离线依赖、工作区备份恢复及迁移步骤见[部署与维护手册](部署与维护手册.md)。

本机已登记同事方案的工作区使用 `启动20261012升级版.cmd`，对应 `runtime-20261012`。常规启动仍使用原工作区。原始MDB、交付ZIP和计算结果通过工作区备份迁移，不随源码克隆自动恢复。

## 目录

| 目录 | 用途 |
| --- | --- |
| `frontend-demo/app` | 前端源码、公共组件、案例清单、静态资料与测试 |
| `backend` | 统一服务、模型适配、资料库、任务与状态管理 |
| `backend/vendor/model` | 已登记来源的数值实现、基础配置和运行资料，升级清单核验每项变动 |
| `config` | 安装目录相对配置 |
| `scripts` | 安装、启动、打包、备份与验证脚本 |
| `方案文档` | 平台方案与模型说明 |

`runtime`、运行环境、依赖、构建产物、历史快照、原始交付包及测试输出保留在本机，由 `.gitignore` 排除。工作区资料通过完整备份管理。Git 收录的模型及静态资料使用 `.gitattributes` 保留文件字节，保持来源摘要可核验。

## 开发与验证

前端检查在 `frontend-demo/app` 中执行 `npm test`，统一网页构建使用 `npm run build:unified`。后端和真实模型的验证范围见[统一系统验收记录](统一系统验收记录.md)，完整操作见[平台实操流程](平台实操流程.md)，接口见[API](backend/API.md)。

日常修改完成后，在项目根目录提交并推送：

```powershell
git status
git add .
git commit -m "说明本次修改"
git push
```

提交身份保存在本仓库的本地 Git 配置中；GitHub 登录凭据由系统凭据管理器保存，不写入仓库。
