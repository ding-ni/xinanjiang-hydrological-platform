# 新安江水文模型平台 · 前端 Demo 使用说明

Vue 工程位于 `app/`。现在有两种入口：根目录 `启动统一平台.cmd` 是真实前后端统一入口；本目录 `打开平台.bat` 仍是独立前端 Demo。南安溪 1 km 已接通诊断模拟、场次率定、状态续算和成果管理，正式业务预报仍未开放。完整操作和边界见根目录 `统一系统说明.md`。

以下保留独立 Demo 和目标业务流程说明，“未接入后端”等旧描述仅适用于独立 Demo，不代表当前统一平台。旧静态页面仍归档于 `归档/历史原型/`，不参与计算。

当前已登记的并行案例为：南安溪-徐畈、里龙普曲、色林错。案例资料和完成程度不同，详见 `app/案例包规范.md` 与 `app/数据目录说明.md`。

## 启动

已安装 Node.js LTS 时，日常使用直接双击 **`打开平台.bat`**。平台地址为 `http://127.0.0.1:5173/`。

| 文件 | 用途 |
| --- | --- |
| `打开平台.bat` | 日常入口。服务未运行时自动启动，等待就绪后打开浏览器；已运行时直接打开。 |

日常只需双击 `打开平台.bat`，不需要运行其他批处理脚本。

代码更新后 Vite 会自动刷新。若浏览器仍保留旧资源，请按 `Ctrl+F5` 强制刷新。不要直接打开 `归档/历史原型/` 中的旧 HTML；它们不属于当前 Vue 应用。

当前 Demo 不需要数据库、模型计算服务或安装包即可启动。`启动演示.bat` 只适用于已有构建/静态目录的本地预览；开发调试优先使用 `打开平台.bat`。

目录和静态资源路径已按可迁移方式组织，但这不等于完全离线：地图文字目前仍使用外网字体服务。断网时文字标注可能不完整；本轮未下载或打包离线字体。

## 页面与未来业务流程

以下内容描述平台的目标业务流程，帮助统一页面和案例组织；当前版本只完成前端交互与静态资料展示，未完成正式计算闭环。

### 0. 数据与模型准备

未来由模型员完成一次性配置。当前 Demo 只展示已登记的轻量资料和目录，不会从本机数据库或原始 NetCDF 自动生成生产输入：

1. 从外部资料源接收雨量、水位、流量和预报降水。
2. 完成资料整编和质量控制，保留资料批次及处理记录。
3. 将站点实测雨量插值为空间降水场，并把数值预报降水转换到模型计算尺度。
4. 配置计算尺度、流域分区、新安江产流、坡面汇流和河网汇流方案。
5. 在后端模型服务中使用实测水雨情和降水场完成率定与验证，再发布生产模型方案。

当前界面可以选择 `1 km` 与 `0.1°` 等模型尺度，但不同案例的资料完整度不同，不能把尺度选择理解成已经具备两套完整生产模型。未来每个尺度应有各自的 DEM、计算网格、降水场、参数版本、状态节点和预报档案；网格是分布式模型的计算单元，入湖流域负责参数分区、坡面汇集和河网汇流。

资料目录按资料对象管理，不按“历史/实时”分成两套。已经发生的观测值、新接入的观测值和以后追加的最新观测值都写入同一套站点资料、出口水文资料和降雨场目录；目录更新后，页面按目录中的时间范围重新计算可用窗口。页面中的“最新共同覆盖时段”指雨量与出口水文资料都覆盖到的最新时段，不是另一种数据类型。洪水场次是对一段洪水过程的登记，场次表中的“变更记录”只记录名称、时间、状态和资料统计的修改。

### 1. 雨水情监视（前端演示）

页面可查看已随 Demo 提供的降水站、湖泊水位站、入湖控制断面和资料目录样例。点击站点可查看静态预览或逐小时过程线；南安溪支持“最新共同覆盖时段”“指定时段”和“指定洪水场次”等交互。真实实时到报、质量控制和完整年度资料仍需未来资料服务提供。

### 2. 预报作业（目标流程，当前不计算模型）

当前页面只保存选择条件、请求草稿和前端演示状态，不提交模型任务，也不生成正式预报成果。目标流程为：

1. 选择单个入湖断面，或选择“色林错全湖”一次计算四个入湖流域。
2. 系统采用最新完整雨水情资料时刻作为起报时刻，实测过程终点与预报过程起点为同一时刻、同一流量值。
3. 读取最近一次已保存的流域蓄水状态，用此后的实测雨水情续算到起报时刻。
4. 选择预见期和预报降水发布时次；起报前采用实测降水场，起报后采用所选时次的逐小时预报降水场。
5. 读取当前尺度已发布的生产方案，分别计算降雨径流、融雪径流、冰川融水和地下径流，经分级河网形成四个入湖过程。
6. 后端全湖预报把四口入流、湖面降水、湖面蒸发和渗漏纳入湖泊水量平衡，给出总入湖洪峰与预报湖位。
7. 检查洪峰、峰现、洪量、湖位、断面过程和分布式产流结果。
8. 保存结果或发布预报，并保存本次计算后的流域状态，供下一次作业续算。

过程线默认展示起报前 48 小时实测，预报从起报时刻连续衔接。资料异常作为质控结果记录，不再设置“人工复核、强制运行、强制原因”等额外表单。

### 3. 状态续算（目标流程）

状态页的目标是管理可用于下一次起报的流域蓄水状态，同时查看预报期间各状态量的空间演变。当前没有后端状态快照，页面展示仅用于验证交互；正式 WU、WL、WD、W/WM、S 和时段产流深 R 需由模型服务计算。

### 4. 率定验证（目标流程）

未来使用后端提供的实测序列和空间降水场，支持连续率定与洪水场次率定。当前页面只展示场次目录和表单结构，不执行优化或发布生产方案。正式率定需由后端计算并返回候选参数、指标和审核结果。

### 5. 运行档案（前端演示）

当前只用于验证运行记录页面的筛选、过程线和条件回填交互；正式运行记录、参数版本和审核轨迹应由后端或版本化资料服务提供。

### 6. 模型与资料（目标管理范围）

未来模型员和系统管理员可维护资料目录、计算尺度、产汇流方案、站网关系、洪水场次、参数方案和状态续算规则。当前版本只维护前端清单和静态预览，不提供正式资料管理后台。

### 技术资料

未来整编水雨情可以由数据库或资料服务管理，实测与预报空间降水场可采用 NetCDF 等专业格式。当前 Demo 只读取随项目提供的 JSON、GeoJSON、PNG 和小型预览文件；原始数据库、NetCDF、栅格和旧程序不属于浏览器运行时。色林错项目的河网资料说明仍作为案例来源记录保留。

## 前后端边界（当前仅前端）

当前版本是可独立启动的前端程序，但没有接入模型计算服务。界面中的每个工作区都以 `流域 + 项目 + 模型配置` 为边界保存：流域切换不应复用另一流域的配置、状态草稿、率定实验或预报档案；色林错 `1 km` 与 `0.1°` 也分别保存。

前端负责组织作业、展示输入血缘和生成请求草稿，不能替代数值模型服务：

1. 当前前端形成资料选择和质控摘要草稿；未来后端应生成可追溯的观测快照 ID。
2. 状态续算由后端用观测快照和上一状态计算，并返回正式状态快照。预报页只选择和锁定它，不能由预报结果反写出新的起报状态。
3. 一次预报运行绑定一个起报时刻、模型配置、参数版本、状态快照、观测/降水强迫快照和情景，并产出该范围内的多个断面成果。页面中的“成果聚焦对象”仅改变查看对象，不会把它拆成多个独立预报。
4. 多场实测洪水属于率定实验的事件集，分别承担率定、验证和独立检验角色；它们不是一次实时预报中的多个“洪水”。率定的优化、指标计算、候选参数审核和生产发布由后端执行。
5. 后端未接入时，前端只保存资料选择、运行条件和任务请求草稿；浏览器内的演示结果只用于检查交互，不标记为正式计算成果。未来接入后，以服务端生成的运行 ID、状态和成果替换演示结果。

建议后端以以下资源组织接口：`/contexts`、`/observation-snapshots`、`/state-snapshots`、`/forecast-runs`、`/forecast-products`、`/calibration-experiments`、`/parameter-candidates`。每个资源都应携带完整的流域、项目和模型配置标识。

## 验证

```bash
cd app
npm test
npm run build
```

浏览器级案例隔离测试（需已安装 Python、Playwright 及其 Chromium；这些是测试依赖，不是前端运行依赖）：

```bash
python tests/case_catalog_smoke.py
```

先在另一个终端的 `app` 目录运行 `npm run dev`，再运行测试。测试在内存中登记一个无资料案例，不向案例目录写文件；覆盖四个案例、两种尺度和六个页面。可用 `--base-url` 指定已启动的站点地址，例如测试部署在 `/dist/` 子目录的构建结果。

本项目目前是前后端分离中的前端部分。`xajParamEngine` 仅用于无后端时检查参数交互和页面闭环，不是完整的新安江模型数值解；正式模拟、率定和预报成果在未来接入模型服务后才能产生。
