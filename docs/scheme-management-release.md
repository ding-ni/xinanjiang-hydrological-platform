# 方案、参数与成果管理更新（2026-10-15）

> 资料供数、同事方案迁移及Git交付安排已由[2026-10-16合并实施说明](historical-database-schemes.md)更新。以下保留上一版功能与数值验收记录。

## 使用方式

建立项目方案 → 选择洪水、资料及用途 → 设置初始参数、搜索范围、算法预算和起算条件 → 保存版本 → 计算 → 保存成果 → 按需另存参数与完整末状态。

- 方案打开后为查看状态。过程浏览、筛选、翻页不修改计算条件。点击“编辑方案”后才可改选场次、用途和参数。草稿自动暂存；“保存新版本”“放弃修改”“另存方案”由用户明确选择。离开页面或计算前检查修改。不同页面使用方案版本和草稿版本检查冲突。
- 名称旁的✎只修改名称。参数库数值不原地覆盖；从新的计算成果另存参数。参数记录含产流、汇流、蒸散发与起算规则。可以从参数库进入模拟，或带入方案作为初值。
- 历史成果跨方案版本保留。“按原条件复算”读取数值任务冻结请求，跳过当前页面选择、资料准备默认值和草稿。列表提供可复算状态及缺失原因；真正计算前再次校验内容摘要。
- 新计算自动保存当前平台计算程序快照。历史计算可以从本地Git提交恢复原程序，摘要必须与成果记录完全一致。当前工作区已恢复`c570027`对应的`57ef5ab2…`程序，可供升级前成果复算和末状态续算。原模型源文件和输入资料仍须完整，缺失时明确拒绝；不会伪造历史。
- 实际工作区为`runtime-20261012`。已有备份`开发产物/backups/20261015-scheme-management-before`保留。后续工作区备份包含计算程序快照；Git管理源码、测试与说明，按用户后续要求完成提交与推送。

## 资料与界面

公共目录226场。原方案另外使用13个公共目录没有的编号；其中两个与公共目录同号的场次还采用了不同边界。这两条原边界单独保存为方案覆盖记录，公共目录原边界不被改写；239表示226加13个额外编号，并不是新增了13场公共洪水。

率定列表默认每页10场，内部滚动。雨水情场次选择器读取完整公共目录，可以搜索、按年份筛选和滚动；覆盖标记以当前资料登记目录为依据，真正计算仍须逐时检查。模型与资料中以中文显示徐畈（二）和雨量站名称，站号、MDB别名保留在详情。资料处理记录只作为输入追溯信息。

新增或修改场次的新版本统一从完整历史库重新准备全部选用雨流资料；同事原方案及旧成果复算继续使用原冻结输入。雨流、蒸散发与预热均纳入检查，缺资料列明时段。Excel自动识别、字段映射和入库留待后续。

产流、坡面与河道人工试调使用同一参数控件。模拟状态从成果、洪水过程进入，过程线和时间轴选择状态时刻；末状态可命名并继续模拟。状态库保留独立初始化入口。日常进阶诊断仅保留河道流量查询、汇流与拓扑设置；原诊断任务记录仍保留。

## 率定与性能

初始参数、参与搜索的参数、算法与预算、起算条件分开设置。搜索范围在一张表编辑；取消勾选保留范围，模板只改上下限。默认分场预热7天，原连续成果沿用原连续起点。默认差分进化120次/种群12，另有480/24、960/48；达到预算上限不标作收敛。文献来源及适配见`search-range-sources.md`。

MDB单次查询上限60秒，长时段分块；真正超时继续缩小区间，失败时报告具体时段。查询只用不可变数据库副本。Numba 0.60.0与llvmlite 0.43.0已锁定、安装并下载对应Python3.9离线wheel；首次编译显示预热状态。完全相同候选只在同一冻结任务内复用评价，只搜索汇流参数时复用固定产流过程。不同产流参数之间不共用状态。

数值对照使用同一MDB输入、110个网格、相同参数/PET/初态，保留完整过程与末状态检验，实测如下（秒）：

| 条件 | 驱动小时 | Python | 首次编译并运行 | 编译后再次运行 |
| --- | ---: | ---: | ---: | ---: |
| 单场，7天预热 | 385 | 0.330 | 43.307 | 0.016 |
| 7个物理洪水组分场预热 | 4788 | 2.981 | 25.796 | 0.222 |

三组流量、产流末状态、汇流末状态最大差为0，指标一致。这只测产汇流前向计算，排除资料读取、搜索器与逐时状态落盘，不代表完整率定加速倍数。各组使用新建无磁盘缓存的JIT分派器，首次计时包含编译；正常工作区会复用磁盘编译缓存。结果在`开发产物/numeric-acceptance/benchmark.json`，复测脚本为`scripts/benchmark_numeric_acceleration.py`。

计算成果分别记录资料准备、搜索、最终评价、末状态生成和总操作耗时。末状态生成耗时包含最佳参数重算及状态保存。评价进度提供剩余时间估计与缓存命中数。首次编译、评价预算和连续驱动长度都会影响耗时。

新增/补齐接口：

- `model-schemes/{id}?revision=N`：读取独立保存版本。
- `model-schemes/{id}/draft`、`discard-draft`：草稿与放弃，携带`revision`和`draftRevision`。
- `model-schemes/{id}/rename`、`parameter-schemes/{id}/rename`：独立名称更新。
- `operations`提交`operation: rerun, sourceTaskId: ...`：冻结条件复算。
- 任务、操作列表的`replayability`：可用性与缺失原因；`availability-only`不替代计算前的摘要校验。
- `states/{id}/metadata`：带元数据版本的命名收藏，不改数值状态。
- `database/station-directory`：完整中文站名及MDB别名。
